# LLM Architecture Generation: Analysis and Results

This repository contains the complete set of artifacts from an experiment on generating software architectures using the o3 OpenAI language model. The study focuses on comparing the effectiveness of **zero-shot** versus **few-shot** prompting techniques.

Below is a detailed description of the directory structure and the contents of each file.

---

## Repository Structure and File Descriptions

### 1. Main Analysis Notebook
- **File:** `llm_architecture_generation.ipynb`
- **Description:** This Jupyter Notebook is the centerpiece of the project. It contains all the Python code used for data loading and processing.

### 2. Summarized Results and Charts
- **File:** `LLM Evaluation Results.xlsx`
- **Description:** This Excel spreadsheet provides a high-level, structured summary of the experiment's findings. It contains cleaned data, final comparison tables, and charts that visualize the performance differences between the prompting techniques. This file is the best place to get a quick overview of the results.

### 3. Raw Model Outputs (`\Results`)

The raw, unprocessed outputs from the OpenAI model are organized into the following two directories based on the prompting technique used. The files within are in CSV format and named according to the project they correspond to.

#### `Results/Zero-Shot Results/`
- **Description:** This folder contains the raw results generated using **zero-shot prompting**. In this approach, the model was asked to generate an architecture with no prior examples provided in the prompt.

#### `Results/Few-Shot Results/`
- **Description:** This folder contains the raw results generated using **few-shot prompting**. In this method, the model was provided with one or more examples of desired outputs within the prompt to guide its response.

## 2. Setting Up and Using a Python Virtual Environment 🔑

To ensure that your project has the correct dependencies without interfering with other projects on your system, it's essential to use a virtual environment. This guide will show you how to create an environment, install packages from a `requirements.txt` file, and activate it to run your code.

### Step-by-Step Guide

Follow these steps in your terminal, from the `\LLM Architecture Generation` directory of your project (the same folder where requirements.txt is located).

#### 1. Create the Virtual Environment

We will use Python's built-in venv module to create a dedicated environment folder. A standard convention is to name this folder .venv.
```bash
# The format is: python3 -m venv <folder_name>
python3 -m venv .venv
```

After running this command, you will see a new folder named .venv in your project directory. This folder contains a private copy of the Python interpreter and pip.

#### 2. Activate the Virtual Environment

To use the environment, you must "activate" it. The activation command is different for Windows and for macOS/Linux.

#### On macOS / Linux (bash/zsh):
```bash
source .venv/bin/activate
```
#### On Windows (Command Prompt / PowerShell):
```bash
.\.venv\Scripts\activate
```
How do you know it worked? After activation, your terminal prompt will change to show the environment's name, like this:
(.venv) C:\Users\YourUser\path\to\project>

#### 3. Install Dependencies from `requirements.txt`

With the environment active, you can now install all the necessary packages listed in your `requirements.txt` file with a single command.

```bash
pip install -r requirements.txt
```
This command tells pip to read the specified file and install the exact versions of all the libraries listed inside.

### 5. 🔍 Checking for Successful API Calls

To interact with the OpenAI API, the notebook uses a helper function called `run_prompt`. This function wraps the API call and returns the model’s output. Here is the implementation:

```bash
def run_prompt(prompt, model="o3", temperature=0.3):
    response = client.chat.completions.create(
        model=model,
        messages=[{"role": "user", "content": prompt}],
        temperature=temperature,
    )
    return response.choices[0].message.content.strip()
```

* **How to Know if the API Call Worked:**

    If the call is successful:

    * The function will return a string containing the model’s response.
    * You can print or log this output to verify its content.

    If there is a failure:

    * You will likely get an exception (e.g., due to an invalid API key, network issue, or exceeded quota).
    * To make debugging easier, it is recommended to wrap the function call in a try-except block like so:

    ```bash
        try:
            result = run_prompt("Generate a software architecture for a movie booking system")
            print(result)
        except Exception as e:
            print("API call failed:", e)
    ```
