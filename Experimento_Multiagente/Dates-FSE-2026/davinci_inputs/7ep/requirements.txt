- O sistema deve permitir o cadastro de bibliotecários por meio de nome de usuário e senha.
- O sistema não deve permitir o cadastro de um bibliotecário com nome de usuário já existente.
- O sistema deve exigir o preenchimento de nome de usuário e senha no cadastro.
- O sistema deve aceitar apenas senhas consideradas fortes o suficiente para uso seguro.
- O sistema deve rejeitar senhas muito curtas.
- O sistema deve permitir que bibliotecários autenticados informem nome de usuário e senha para entrar no sistema.
- O sistema deve conceder acesso somente quando usuário e senha corresponderem exatamente ao cadastro existente.
- O sistema deve negar o acesso quando usuário ou senha estiverem incorretos ou não forem informados.
- O sistema deve tratar credenciais de bibliotecários de forma protegida, sem depender da senha em texto puro para validação posterior.
- O sistema deve responder de forma clara a tentativas de acesso negadas, sem expor detalhes sensíveis do processamento interno.
- O sistema deve permitir o cadastro de livros no acervo por título.
- O sistema não deve permitir o cadastro duplicado de um mesmo livro.
- O sistema deve informar quando a tentativa de cadastro de livro falhar por falta de título.
- O sistema deve permitir a exclusão de livros já cadastrados.
- O sistema não deve permitir a exclusão de livros que nunca foram cadastrados.
- O sistema deve excluir também o vínculo de empréstimo quando um livro removido estiver emprestado.
- O sistema deve permitir listar todos os livros cadastrados.
- O sistema deve permitir consultar um livro por identificador.
- O sistema deve permitir consultar um livro por título.
- O sistema deve permitir listar apenas os livros disponíveis para empréstimo.
- O sistema deve informar quando não houver livros cadastrados ou quando uma busca não encontrar resultado.

- O sistema deve permitir o cadastro de leitores aptos a receber empréstimos.
- O sistema não deve permitir o cadastro duplicado de um mesmo leitor.
- O sistema deve informar quando a tentativa de cadastro de leitor falhar por falta de nome.
- O sistema deve permitir a exclusão de leitores já cadastrados.
- O sistema não deve permitir a exclusão de leitores que nunca foram cadastrados.
- O sistema deve excluir também os vínculos de empréstimo quando um leitor removido possuir livros emprestados.
- O sistema deve permitir listar todos os leitores cadastrados.
- O sistema deve permitir consultar um leitor por identificador.
- O sistema deve permitir consultar um leitor por nome.
- O sistema deve informar quando não houver leitores cadastrados ou quando uma busca não encontrar resultado.
- O sistema não deve aceitar, na mesma consulta, busca simultânea por identificador e por nome/título.

- O sistema deve permitir registrar o empréstimo de um livro para um leitor cadastrado.
- O sistema deve registrar a data em que o empréstimo foi realizado.
- O sistema não deve permitir empréstimo para pessoa que não esteja cadastrada como leitora.
- O sistema não deve permitir empréstimo de livro que não esteja cadastrado.
- O sistema não deve permitir empréstimo de livro que já esteja emprestado a outra pessoa.
- O sistema deve permitir que um mesmo leitor tenha mais de um livro emprestado ao mesmo tempo.
- O sistema deve garantir que um mesmo livro esteja emprestado para apenas um leitor por vez.
- O sistema deve informar claramente quando um empréstimo não puder ser concluído.
- O sistema deve consultar os dados do leitor e do livro durante o registro do empréstimo, garantindo que as informações estejam atualizadas.
- O sistema deve preservar a consistência entre livros, leitores e empréstimos, evitando registros inválidos ou contraditórios.

- O sistema deve permitir limpar os dados e a estrutura da base para reiniciar o ambiente.
- O sistema deve permitir recriar a estrutura da base quando necessário.
- O sistema deve permitir restaurar rapidamente o ambiente para um estado limpo e pronto para novos testes.
- Para executar essas operações de reinício, o sistema deve coordenar as diferentes áreas funcionais envolvidas, garantindo que seus dados sejam restaurados de forma consistente.

- O sistema deve permitir somar dois números inteiros informados pelo usuário.
- O sistema deve permitir calcular valores da sequência de Fibonacci com mais de uma abordagem de cálculo.
- O sistema deve permitir calcular resultados da função de Ackermann com mais de uma abordagem de cálculo.
- O sistema deve informar erro quando os serviços matemáticos receberem valores fora do formato esperado.
- O sistema deve oferecer um catálogo de serviços para consulta e teste de endpoints disponíveis.

- O sistema deve registrar as principais operações para apoiar rastreabilidade e análise de problemas.
- Para isso, as operações relevantes dos fluxos de cadastro, autenticação, consulta e empréstimo devem ser reportadas a um mecanismo central de registro de eventos.
- O sistema deve manter esse registro de forma desacoplada das áreas de negócio, permitindo rastrear falhas e comportamentos sem acoplar a persistência da auditoria aos domínios funcionais.

- O sistema deve poder ser utilizado por meio de formulários web simples, com retorno rápido e legível para cada ação.
- O sistema deve oferecer mensagens objetivas de sucesso, negação e erro para orientar o usuário.
- O sistema deve reduzir digitação manual em fluxos repetitivos, como empréstimo de livros, por meio de listas ou sugestões.
- O sistema deve facilitar o preenchimento do empréstimo exibindo opções de livros disponíveis e leitores cadastrados.
- O sistema deve adaptar a forma de escolha na tela de empréstimo conforme a quantidade de opções disponíveis.
- O sistema deve bloquear o campo de seleção de empréstimo quando não houver dados disponíveis para escolha.
- O sistema deve exibir o resultado de cada operação de forma imediata após o envio do formulário.

- O sistema deve manter comportamento consistente tanto pela interface principal quanto pelos endpoints de consulta e envio de dados.
- O sistema deve funcionar em navegadores comuns e considerar uso em telas menores.
- As regras centrais de cadastro, autenticação, consulta e empréstimo devem ser verificadas de forma repetível por testes automatizados.
- O sistema deve estar organizado por domínios de negócio, favorecendo manutenção e ampliação das funcionalidades.

- O código implementa regras de exclusão de livros e leitores, mas a tela principal atual não expõe esses comandos diretamente.
- O sistema possui autenticação de bibliotecários, mas o código atual não mostra bloqueio de sessão nas demais operações da biblioteca.
- A parte de biblioteca e autenticação é o núcleo de negócio mais claro da aplicação; os módulos matemáticos aparecem como funcionalidades auxiliares de demonstração.
